## 2.1.2 Characteristics of a LAN and a WAN

> [!question] 9618 | Characteristics of a LAN [2]
> Describe the characteristics of a LAN (local area network).
>
>> [!success]- Answer — 4 points for 2 marks
>> - Covers a small geographical area
>> - Normally privately owned // dedicated infrastructure // not controlled by external organisations
>> - Can use wired or wireless communication
>> - Has a high data transfer rate
>>
>> *Latest: `9618_w25_qp_12_sc_5.a`*

> [!question] 9618 | Characteristics of a WAN [2]
> Describe the characteristics of a WAN (wide area network).
>
>> [!success]- Answer — 4 points for 2 marks
>> - Covers a large geographical area
>> - External / public infrastructure is used
>> - Non-dedicated hardware
>> - Connections are often virtual rather than physical
>>
>> *Latest: `9618_w24_qp_13_sc_9.a`*

> [!question] 9618 | Differences between a LAN and a WAN [2]
> State **two** ways in which a WAN is different from a LAN.
>
>> [!success]- Answer — 4 points for 2 marks
>> - A WAN covers a large geographical area; a LAN covers a small geographical area
>> - A WAN may use non-dedicated hardware; the hardware in a LAN is usually dedicated
>> - A WAN uses external / not company-owned transmission media; a LAN's transmission media is usually company owned
>> - A LAN has a high data transfer rate; a WAN has a lower data transfer rate
>>
>> *Latest: `9618_s25_qp_12_sc_6.a`. `9618_s23_qp_13_sc_2.a` adds: the ownership of a LAN is private, a WAN can be private or public; a LAN is usually more secure because protection is easier to implement.*

## 2.1.4 Thin-client and thick-client

> [!question] 9618 | Characteristics of a thin-client, applied [4]
> Identify **two** characteristics of a thin-client and describe how each is used in a given software system. *(1 mark characteristic + 1 mark application, ×2.)*
>
>> [!success]- Answer — 6 points for 4 marks
>> - Data is not stored on the client computer … the data is stored on the server instead
>> - The client computer is reliant on access to the server … the user cannot work if the server goes down
>> - The client is heavily reliant on the network / internet connection … the software will not operate without network access
>> - The client requires few local resources / little memory … low-specification devices can still run the software
>> - The client performs minimal functions / processes … it transmits requests and the server sends back the response
>> - The client only displays the results returned by the server
>>
>> *Latest: `9618_s24_qp_12_sc_3.b`*

> [!question] 9618 | Describe a thick-client model [2]
> Describe what is meant by a **thick-client** model.
>
>> [!success]- Answer — 4 points for 2 marks
>> - The server performs minimal / some processing for the client
>> - The clients do most of their own processing // work independently
>> - Most of the resources are installed locally on the client
>> - The client can function without a constant connection to the server
>>
>> *Latest: `9618_s23_qp_12_sc_1.e`*

>> [!success]- Answer — 4 points for 2 marks
>> - The server performs **all** processes required by the task and/or data storage
>> - The clients **only** send requests to the server
>> - … and display the returned results
>> - The clients perform no processing of their own
>>
>> *Latest: `9618_s23_qp_13_sc_2.c`*

> [!question] Inferred | Differences between thin-client and thick-client [4]
> Give **two** differences between a thin-client and a thick-client model. *(2 marks per difference.)*
>
>> [!success]- Answer — 6 points for 4 marks
>> - A thin-client needs a permanent connection to the server …
>> - … whereas a thick-client can work independently of a server
>> - A thin-client uses the server's processing power …
>> - … whereas a thick-client uses its own local processing power
>> - A thin-client does not function offline, whereas a thick-client can function offline
>> - A thin-client needs few local resources, whereas a thick-client has resources installed locally
>>
>> *Tariff set to 4: the bullet ends "and the differences between them", and 9618 marks paired-expansion questions at 4.*

> [!question] Inferred | Benefits and drawbacks of thin-client for an organisation [4]
> Describe **one** benefit and **one** drawback to an organisation of using thin-clients. *(2 marks each.)*
>
>> [!success]- Answer — 6 points for 4 marks
>> - Benefit: cheaper client devices can be used … because the processing is done by the server
>> - Benefit: software updates and security are managed centrally … so only the server needs updating
>> - Benefit: new clients are easy to add

>> [!success]- Answer — 6 points for 4 marks

> [!question] 9618 | How packets are transmitted in a star topology [3]
> Describe how packets are transmitted between two hosts using a star topology.
>
>> [!success]- Answer — 5 points for 3 marks
>> - The sending device sends the packets to the switch
>> - The switch checks the destination address on each packet
>> - … and sends them **only** to the intended receiver
>> - The switch uses the stored MAC addresses of the connected devices to do this
>> - Other devices on the network do not receive the packets
>>
>> *Latest: `9618_w25_qp_12_sc_5.c`. `9618_s24_qp_13_sc_5.b` accepts "switch/router/central device".*

> [!question] 9618 | Describe a mesh topology [2]
> Describe what is meant by a **mesh** topology.
>
>> [!success]- Answer — 4 points for 2 marks
>> - All computers are connected to at least one other device
>> - There are multiple routes between devices
>> - The computers can act as relays, passing packets on towards the final destination
>> - In a full mesh every computer is connected to every other computer
>>
>> *Latest: `9618_s23_qp_13_sc_2.b.i`*

>> [!success]- Answer — 4 points for 2 marks

>> - No / fewer collisions
>> - New nodes can be added without interruption or interfering with other nodes
>>
>> *Latest: `9618_s23_qp_13_sc_2.b.ii`*

>
>> [!success]- Answer — 5 points for 3 marks

> [!question] Inferred | How packets are transmitted in a bus topology [3]
> Describe how packets are transmitted between two hosts using a bus topology.
>
>> [!success]- Answer — 5 points for 3 marks
>> - The sending device puts the packet onto the single shared bus cable
>> - All devices on the cable receive / listen to the packet
>> - Each device checks the destination address on the packet
>> - Only the device whose address matches accepts it
>> - All other devices ignore the packet
>>
>> *Tariff set to 3 to match the star version, `9618_w25_qp_12_sc_5.c`.*

> [!question] Inferred | Drawbacks of star and mesh, and advantages of bus [4]
> Describe **one** drawback of a star topology and **one** drawback of a mesh topology. *(2 marks each.)*
>
>> [!success]- Answer — 6 points for 4 marks
>> - Star: the central switch is a single point of failure …
>> - … if the switch fails, every device loses access to the network and its resources
>> - Star: expensive to install, because of the switch and the extra cabling needed
>> - Mesh: requires a large amount of hardware, cabling and switches …
>> - … so it has a high set-up cost
>> - Mesh: hard to scale, because adding a new device means adding many new connections
>>
>> *Tariff set to 4 by the pattern of paired-expansion questions.*

> [!question] SME | Bus topology — terminators and behaviour [3]
> Describe how a bus topology is constructed and how devices read data from it.
>
>> [!success]- Answer — 5 points for 3 marks
>> - All devices are connected by one single bus cable
>> - The cable is terminated at each end
>> - The terminators stop the signal bouncing back and causing errors
>> - Each device listens to the electrical signals on the cable
>> - Each device checks packets for its own address and ignores those it does not recognise
>>
>> *Tariff set to 3. "Terminator" appears in no mark scheme in this topic.*

> [!question] SME | Star topology with a hub instead of a switch [2]
> Explain how traffic on a star topology differs when the central device is a hub rather than a switch.
>
>> [!success]- Answer — 4 points for 2 marks
>> - A hub sends the traffic to **all** devices on the network
>> - … each device checks the address and accepts it if it matches, otherwise ignores it
>> - A switch sends the traffic **only** to the device whose address matches
>> - So a hub creates unnecessary traffic and is less secure
>>
>> *Tariff set to 2.*

> [!question] SME | Mesh — full vs partial, routing vs flooding [4]
> Describe the difference between a full and a partial mesh, and describe **two** ways packets can travel on a mesh network.
>
>> [!success]- Answer — 6 points for 4 marks
>> - Full mesh: every computer is connected to every other computer
>> - Partial mesh: only some devices are interconnected, which is cheaper and more practical
>> - Routing: devices are given routing logic so packets are sent by the shortest route
>> - … each device acts like a router
>> - Flooding: all packets are sent to all devices with no routing logic
>> - … which can cause network flooding and performance problems
>>
>> *Tariff set to 4. Neither "partial mesh", "routing" nor "flooding" appears in a mark scheme here.*

> [!question] SME | Advantages and disadvantages of a hybrid topology [4]
> Give **two** advantages and **two** disadvantages of a hybrid topology.
>
>> [!success]- Answer — 6 points for 4 marks
>> - Advantage: combines the strengths of each topology, e.g. the reliability of mesh with the simplicity of bus
>> - Advantage: flexible — different parts of the network can be optimised for different needs
>> - Advantage: scalable — new segments can be added without changing the whole setup
>> - Advantage: a failure in one part does not necessarily affect the rest
>> - Disadvantage: complex to design, needing careful planning to combine different topologies
>> - Disadvantage: expensive, and harder to troubleshoot because different parts follow different rules
>>
>> *Tariff set to 4.*

> [!question] 9618 | How CSMA/CD is used in a bus network [4]
> Describe how Carrier Sense Multiple Access / Collision Detection (CSMA/CD) is used in a bus network.
>
>> [!success]- Answer — 7 points for 4 marks
>> - CSMA/CD is a protocol used to detect and prevent collisions in a bus topology
>> - Before transmitting, a device checks if the channel is busy
>> - If the channel is busy the device waits // if the channel is free the data is sent
>> - Because there is more than one computer connected to the same transmission medium …
>> - … two workstations can start to transmit at the same time, causing a collision
>> - If a collision is detected by the device, transmission is aborted / a jamming signal is transmitted
>> - Both devices wait a (different) **random** time and then try again
>>
>> *Latest: `9618_w22_qp_11_sc_8`. `9618_w25_qp_12_sc_5.d` adds: the random time is increased if there are multiple collisions.*

> [!question] 9618 | Tasks performed by devices under CSMA/CD [3]
> State **three** tasks performed by devices to deal with collisions when using CSMA/CD.
>
>> [!success]- Answer — 6 points for 3 marks
>> - To monitor the communications channel
>> - To send data only when there is no data being transmitted / the line is idle
>> - To detect a collision and then stop transmission of further data // transmit a jamming signal
>> - To calculate a **random** wait time / back-off time
>> - … then retransmit the data after that random wait time
>> - Increase the random time if there are multiple collisions
>>

## 2.1.15 URLs and the DNS

> [!question] 9618 | How a web browser uses a URL to access a web page [4]
> A user types a URL into the address bar of a web browser. Explain how the web browser uses the URL to access the web page.
>
>> [!success]- Answer — 8 points for 4 marks
>> - The browser checks its cache for the URL
>> - The browser parses the URL and splits it into its component parts
>> - The browser finds the IP address for the domain name by querying a DNS server
>> - The browser receives the matching IP address from the DNS server
>> - The browser creates a connection with the web server with the matching IP address
>> - A request for the resource is sent to the web server with that IP address
>> - The browser renders and displays the result
>> - The IP address is stored in the browser cache for future use
>>
>> *Latest: `9618_w25_qp_11_sc_7.c` — the only 9618 question in this whole bullet.*

> [!question] 9608 | How a URL is converted into its matching IP address [3]
> Describe how a URL is converted into its matching IP address.
>
>> [!success]- Answer — 6 points for 3 marks
>> - The URL is parsed to obtain the domain name
>> - The domain name is sent to the nearest Domain Name Server (DNS)
>> - The DNS holds a list of domain names and matching IP addresses
>> - The DNS name resolver searches its database for the domain name
>> - If the domain name is found, the IP address is returned to the originator
>> - If it is not found, the request is forwarded to a higher-level DNS; if it is finally not found, an error message is generated
>>
>> *Latest: `9608_s19_qp_11_sc_1.b`. `9608_s16_qp_13_sc_6.e` is the 4-mark version, adding: the original DNS server adds the returned IP address to its cache.*

> [!question] 9608 | Are a domain name and an IP address the same thing? [3]
> An employee states, "A domain name and an IP address are exactly the same thing". State whether this is true or false and justify your choice.
>
>> [!success]- Answer — 5 points for 3 marks
>> - **False**
>> - The IP address is the (physical) address of the server
>> - A domain name is a memorable form for an IP address, and each domain name is linked to an IP address
>> - A DNS is used to translate a domain name into its corresponding IP address
>> - The domain name does not change, but the IP address could change (dynamic)
>>
>> *Latest: `9608_s21_qp_13_sc_6.b`*

> [!question] SME | The DNS hierarchy [3]
> Describe what happens when the nearest DNS server cannot find the domain name.
>
>> [!success]- Answer — 5 points for 3 marks
>> - The request is passed on to a higher-level DNS server
>> - A **root server** is contacted, which points to the correct Top-Level Domain (TLD) server, e.g. `.com`, `.org`
>> - The TLD server points to the **authoritative DNS server** for that domain
>> - The authoritative DNS server responds with the correct IP address
>> - The original DNS server caches the returned address for future requests
>> - **Caution:** the terms root server, TLD server and authoritative server appear in **no** mark scheme in either series. A 9618 answer needs only "passed to a higher-level DNS".
>>
>> *Tariff set to 3.*

> [!question] SME | DNS propagation [2]
> State what is meant by DNS propagation and explain when it is needed.
>
>> [!success]- Answer — 4 points for 2 marks
>> - When a domain is registered, or its server's IP address changes, the DNS records must be updated
>> - The spread of that update across the internet's DNS servers is called DNS propagation
>> - It takes time, because each DNS server must receive the new record
>> - Until it completes, some users may still be directed to the old IP address
>>
>> *Named nowhere in the syllabus or the mark schemes. Tariff set to 2.*
